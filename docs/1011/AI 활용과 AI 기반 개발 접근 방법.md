## 1. AI는 검색엔진과 비슷하다

AI를 잘 활용하기 위해서는 **검색엔진을 사용하는 방식으로 접근해 보는 것이 좋다.**

검색엔진의 내부 알고리즘을 정확히 모르더라도 우리는 원하는 결과를 찾기 위해 다양한 검색어를 입력한다.

AI도 비슷하다.

- 처음부터 정확한 프롬프트를 작성하기는 어렵다.
    
- 여러 번 사용하다 보면 어떤 표현과 키워드가 효과적인지 감이 생긴다.
    
- 상황에 따라 영어가 더 효과적일 수도 있고, 특정 전문 용어를 사용해야 원하는 결과가 나올 수도 있다.
    
- 같은 요구사항이라도 어떻게 설명하느냐에 따라 결과의 품질이 달라진다.
    

**핵심은 많이 사용해 보는 것이다.**

AI를 잘 활용하려면 이론적인 지식도 중요하지만, 직접 사용하면서 시행착오를 경험하는 것이 무엇보다 중요하다.

### AI 활용을 시작할 때

1. 우선 직접 사용하면서 AI가 어떤 일을 할 수 있는지 체감해 보는 것이 좋다.
    
2. 기존 업무 경험과 도메인 지식이 풍부한 사람일수록 유리하다. 실장님 역시 업무에 대한 이해도가 높기 때문에 AI를 활용할 수 있는 영역이 많다.
    
3. 웹 채팅부터 시작해도 되고, IDE나 다양한 AI 도구를 활용해도 된다.
    
4. 처음부터 개발 도구를 사용할 필요는 없다. 아이디어를 구체화하는 것만으로도 충분히 의미가 있다.

## 2. AI로 개발할 때 가장 중요한 접근 방식

### 핵심 ① 바로 개발하지 말고 시안부터 만들어라

AI에게 아이디어를 전달한 다음 곧바로 전체 시스템 개발을 시작하는 것은 비효율적일 수 있다.

**아이디어 구체화 → 시안 제작 → 검토 및 수정 → 개발**

이 순서를 권장한다.

### 왜 시안이 먼저인가?

**1. 수정 비용과 토큰 낭비**

개발이 상당히 진행된 상태에서 화면이나 기능을 수정하려면 관련 프론트엔드와 백엔드 코드를 함께 변경해야 할 수 있다.

- 수정 범위 증가
    
- AI가 분석해야 할 코드 증가
    
- 토큰 사용량 증가
    
- 작업 시간 증가
    
- 기존 기능에 영향을 줄 가능성 증가
    

반면 시안 단계라면 상대적으로 적은 비용으로 여러 가지 방향을 시도할 수 있다.

**2. 기존 결과물에 생각이 고착될 수 있다**

AI는 이미 작성된 코드와 화면을 중요한 참고 자료로 활용한다.

따라서 초기에 만들어진 구조나 디자인을 기준으로 계속 수정하려는 경향이 생길 수 있다.

완전히 새로운 방향을 원하더라도 기존 구현을 조금씩 변경하는 결과가 나올 수 있다.

초기에는 다양한 시안을 비교하고 방향을 결정한 후 개발하는 편이 유리하다.

### 핵심 ② 프론트엔드부터 만들어라

사용자가 실제로 원하는 기능은 대부분 화면과 사용자 경험에서 구체적으로 드러난다.

따라서 사용자 중심의 서비스라면 프론트엔드를 먼저 구현하는 접근이 효과적이다.

**권장 순서**

1. 채팅으로 아이디어와 요구사항 정리
    
2. 화면 시안 제작
    
3. 디자인 및 사용자 흐름 검토
    
4. 프론트엔드 프로토타입 구현
    
5. 필요한 데이터와 기능 구체화
    
6. 백엔드 API 설계 및 구현
    
7. 인프라와 운영 환경 구성
    

프론트엔드가 어느 정도 구체화되면 백엔드에 필요한 API, 데이터 구조, 비즈니스 로직 역시 명확해진다.

반대로 프론트엔드와 백엔드를 모두 구현한 뒤 요구사항을 변경하면 수정 범위가 커진다.

다만 배치, 데이터 처리, 외부 연동 중심 시스템처럼 화면이 핵심이 아닌 프로젝트에서는 백엔드를 먼저 설계하는 것이 적합할 수 있다.

## 3. 백엔드 개발과 아키텍처 구성

프론트엔드에서 필요한 기능이 정리되었다면 본격적으로 백엔드를 개발한다.

가능하다면 이 단계에서 아키텍처까지 함께 고민하는 것이 좋다.

### 서버 환경

AI 기반 개발에서도 실제 서버 실행 환경은 필요하다.

이때 Docker를 활용하면 편리하다.

- 애플리케이션 실행 환경 표준화
    
- 데이터베이스 및 외부 서비스 구성
    
- 개발 환경 재현
    
- 로컬에서 여러 서버나 서비스를 분리해 실행
    
- 실제 운영 환경과 유사한 구조 테스트
    

예를 들어 로컬 Docker 환경을 AWS EC2에 서버를 배포한 것처럼 활용하는 식이다. 단, 컨테이너와 EC2 가상머신은 기술적으로 다른 개념이다.

회사에서는 보안 정책이나 내부 인프라 제약으로 Docker를 사용하지 못할 수도 있지만, 사용 가능한 환경이라면 개발 편의성이 높다.

## 4. AI 도구 활용: 채팅, 브라우저, 컴퓨터 제어

AI는 단순히 질문에 답하거나 소스코드만 작성하는 도구가 아니다.

다양한 도구를 활용하여 실제 작업을 수행할 수도 있다.

### Browser Use

AI가 브라우저를 직접 조작하는 기능이다.

- 웹사이트 방문
    
- 정보 검색 및 수집
    
- 페이지 탐색
    
- 실제 화면 테스트
    
- 웹서비스 동작 확인
    

웹 기반 서비스를 개발할 때 특히 유용하다.

지원되는 AI 개발 도구에서는 필요에 따라 브라우저 조작을 자동으로 수행하기도 한다.

### Computer Use

AI가 컴퓨터의 GUI를 직접 조작하는 방식이다.

브라우저뿐 아니라 지원되는 애플리케이션의 화면을 확인하고 마우스와 키보드 조작을 수행할 수 있다.

### 이미지 생성과 레퍼런스

복잡한 UI, 디자인, 일러스트 등은 이미지 생성 도구를 함께 사용하면 도움이 된다.

Codex처럼 이미지 생성 기능과 연결할 수 있는 개발 환경에서는 시각 자료 생성과 개발을 연계할 수 있다.

특히 **레퍼런스가 있으면 AI가 원하는 결과를 더 정확하게 만들 가능성이 높아진다.**

말로만 설명하는 것보다 기존 웹사이트, 이미지, 디자인 시안을 보여주는 편이 효과적일 수 있다.

## 5. AI 결과물의 품질을 높이는 방법: Skill과 MCP

### AI Slop이란?

AI Slop은 AI가 만들어 낸 낮은 품질의 결과물이나 획일적이고 AI 특유의 느낌이 강하게 드러나는 결과물을 뜻한다.

예를 들어 웹사이트를 제작할 때 다음과 같은 문제가 발생할 수 있다.

- 어디서나 본 것 같은 디자인
    
- 비슷한 레이아웃과 색상
    
- 과도한 효과와 장식
    
- 개성이 부족한 화면 구성
    

AI에게 단순히 "세련되게 만들어 줘"라고 요청하는 것만으로는 원하는 수준의 결과가 나오지 않을 수 있다.

### 프롬프트의 한계

물론 구체적인 프롬프트를 작성하면 결과를 개선할 수 있다.

문제는 좋은 프롬프트를 작성하려면 해당 분야의 전문 지식이 필요하다는 것이다.

디자인을 예로 들면 다음과 같은 지식이 필요할 수 있다.

- 타이포그래피
    
- 색상 조합
    
- 레이아웃
    
- 시각적 계층 구조
    
- 사용자 경험
    
- 디자인 시스템
    

디자인을 전문적으로 배우지 않은 사람이 이러한 요소를 매번 정확하게 지시하기는 어렵다.

### Skill이란?

이러한 전문적인 지식과 작업 지침을 재사용할 수 있도록 정리한 것이 Skill이다.

쉽게 말하면 **AI에게 특정 작업을 수행하는 방법과 기준을 미리 알려주는 지침서**라고 볼 수 있다.

사용자는 매번 긴 프롬프트를 작성할 필요 없이 준비된 Skill을 활용할 수 있다.

**참고 사례: Taste Skill**

[https://github.com/leonxlnx/taste-skill](https://github.com/leonxlnx/taste-skill)

AI가 생성하는 평범하고 획일적인 디자인을 개선하기 위한 프로젝트다.

이런 Skill을 통해 AI에게 디자인 방향과 판단 기준을 제공할 수 있다.

### MCP와 Skill의 차이

|구분|Skill|MCP|
|---|---|---|
|핵심 역할|작업 방법과 전문 지식 제공|외부 도구와 시스템 연결|
|목적|결과물의 품질과 일관성 향상|AI가 수행할 수 있는 작업 확장|
|예시|디자인 가이드, 코딩 규칙|GitHub, DB, 브라우저 연동|

Skill은 **어떻게 잘할 것인가**, MCP는 **무엇을 연결하고 실행할 것인가**에 가깝다.

두 가지를 함께 활용하면 전문적인 작업 지침을 바탕으로 실제 시스템을 조작하는 AI 개발 환경을 구성할 수 있다.

## 6. 기존 서비스를 레퍼런스로 활용하기

AI 개발에서는 모든 것을 처음부터 구상할 필요가 없다.

기존에 잘 만들어진 서비스나 제품을 레퍼런스로 활용하면 아이디어를 빠르게 구체화할 수 있다.

### 사례 ① 미술품 경매 서비스

미술품 경매 플랫폼을 개발한다고 가정해 보자.

기존 경매 서비스인 KREAM 등의 UI와 거래 경험을 참고할 수 있다.

- 상품 목록 및 상세 화면
    
- 가격과 입찰 정보
    
- 경매 진행 상태
    
- 구매 및 거래 흐름
    

기존 서비스의 구조를 참고하되 미술품 경매라는 도메인에 맞게 재설계할 수 있다.

단순히 디자인을 복제하는 것이 아니라 검증된 사용자 경험을 참고하는 방식이다.

### 사례 ② 네트워크 시뮬레이터

Cisco의 네트워크 구성 및 시뮬레이션 도구처럼 특정 분야의 전문 서비스를 AI로 구현하는 것도 생각해 볼 수 있다.

예를 들어 사내 업무에 필요한 네트워크 시뮬레이터를 제작할 수 있다.

- 장비 배치
    
- 네트워크 구성 시각화
    
- 장비 간 연결
    
- 설정 변경
    
- 시뮬레이션 결과 확인
    

기존 제품을 레퍼런스로 삼고 실제 필요한 기능을 중심으로 개발하는 것이다.

이와 같은 접근은 도메인이 바뀌더라도 적용할 수 있다.

## 7. 최종 정리

AI 기반 개발의 핵심은 단순히 코드를 빠르게 작성하는 것이 아니다.

**AI를 반복해서 사용하며 가능성을 이해하고, 원하는 결과를 먼저 구체화한 뒤, 개발 범위를 점진적으로 확장하는 것이다.**

권장하는 전체 흐름은 다음과 같다.

**1단계 — 경험**

AI를 많이 사용하면서 어떤 요청이 잘 작동하는지 감을 익힌다.

**2단계 — 구체화**

채팅과 레퍼런스를 활용해 아이디어를 구체화한다.

**3단계 — 시안**

실제 개발보다 먼저 화면과 사용자 경험을 확인하고 수정한다.

**4단계 — 프론트엔드**

확정한 시안을 기반으로 사용자에게 필요한 기능을 구현한다.

**5단계 — 백엔드**

프론트엔드에서 구체화된 요구사항을 기반으로 API와 비즈니스 로직을 구현한다.

**6단계 — 아키텍처 및 인프라**

필요에 따라 Docker 등의 도구를 활용하여 서버와 운영 환경을 구성한다.

**7단계 — 고도화**

Skill, MCP, Browser Use, Computer Use 등을 활용하여 개발 품질과 자동화 수준을 높인다.

### 핵심 메시지 세 가지

1. **AI는 많이 사용해 보는 것이 가장 중요하다.** 사용 경험이 쌓일수록 원하는 결과를 얻는 방법을 알게 된다.
    
2. **바로 개발하지 말고 시안부터 만들어라.** 초기 방향을 충분히 검토해야 불필요한 수정과 토큰 낭비를 줄일 수 있다.
    
3. **AI에게 모든 것을 말로 설명하려 하지 마라.** 레퍼런스와 Skill 같은 도구를 활용하면 전문 지식과 작업 기준을 효과적으로 전달할 수 있다.
